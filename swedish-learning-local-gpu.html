Building a Swedish learning app with local GPU speech recognition

Yali Nie · September 29, 2026 · Development and Android test log

Tonight I built and tested Svenska Dagligen, a personal Swedish learning prototype. The interface runs in a browser, recordings are analysed on my Ubuntu workstation, and an Android phone reaches the service through private Tailscale HTTPS. This note records the working configuration, the changes that made recording reliable, and the limits of the feedback.

1. The learning problem

I wanted help remembering vocabulary, understanding sentences, and practising Swedish reading. Long words, stress, reduced sounds, and vowel length are particularly difficult. The first prototype focuses on a short learning loop: listen, read aloud, replay the recording, and compare a speech transcript with the target text.

The app has 26 vocabulary entries, meanings and example sentences, a simple spaced-review workflow, article saving, and passage-by-passage recording. Saved articles also show the full text so I can follow a lesson without losing the surrounding context.

Current result: Swedish text-to-speech, microphone recording, audio replay, and local transcription were tested successfully on a Xiaomi Android phone. This is a browser/PWA prototype; no standalone APK was built tonight.

2. Three different audio functions

FunctionImplementationWhat it provides
Read text aloudBrowser SpeechSynthesis and an installed Swedish voiceExample sentences and full-article playback
Play lesson audioAn attached MP3 and the browser audio playerThe original recorded voice
Recognise my recordingfaster-whisper on the Ubuntu GPU serverA transcript and word comparison

Changing the recognition model does not improve the synthetic reading voice. Likewise, pasting a lesson's text does not copy its original audio. A natural lesson recording and browser-generated speech are separate sources.

3. Architecture and files

The phone loads the interface over HTTPS. When I finish recording a passage, JavaScript sends a multipart POST to /analyze on the same origin. Tailscale Serve forwards that request to FastAPI on 127.0.0.1:8080. The server decodes the audio, runs Swedish speech recognition, and returns JSON.

FileRole
index.html, style.css, app.jsMobile interface, study data, article controls, recording and feedback
manifest.webmanifest, sw.js, icon.svgPWA metadata and cached interface assets
server.pyFastAPI transcription endpoint and static-file serving
requirements-server.txtPython dependency ranges

Serving the interface and API from one origin avoids maintaining separate phone-side API addresses. The app uses fetch('/analyze', ...); it does not ask the phone to contact its own localhost.

5. From Whisper medium to KB-Whisper

The initial configuration used the multilingual Whisper medium model. The standalone load test eventually printed “model loaded successfully,” demonstrating that download and CUDA model construction completed. An unauthenticated Hugging Face warning appeared during loading; it was not itself a model-load failure.

In one reading test, the recognised text resembled a video-closing phrase rather than the target sentence. That made it clear that transcription needed more testing. The project was then changed to use KBLab/kb-whisper-large as its default Swedish recognition model. An OpenAI API path was considered and briefly added during development, then removed in favour of the local workflow.

Model selection comes from SV_MODEL. An old environment override such as SV_MODEL=medium still wins over the new default. To make the selected model explicit, use the startup command below and inspect /health.

6. Install, download and start

The workstation kept using the existing project directory below even as the app files were updated. Its “v4” directory name does not mean the running frontend must still be v4.

cd ~/Documents/svenska-dagligen-v4-local-gpu
source .venv/bin/activate
pip install -r requirements-server.txt
sudo apt install ffmpeg

python -u -c "from faster_whisper import WhisperModel; print('Loading KB-Whisper', flush=True); WhisperModel('KBLab/kb-whisper-large', device='cuda', compute_type='float16'); print('Model loaded', flush=True)"

SV_MODEL=KBLab/kb-whisper-large SV_DEVICE=cuda SV_COMPUTE=float16 \
uvicorn server:app --host 127.0.0.1 --port 8080

These commands assume the existing virtual environment. For a fresh checkout, create it first with a Python version supported by the installed dependencies:

python3 -m venv .venv
source .venv/bin/activate

The first load may download model weights. Being able to reach the Hugging Face homepage only checks that endpoint; it does not prove every model-download endpoint is reachable. Keep the model cache when updating the app. At service startup the app can be available before the recognition model has loaded, because server.py creates the model lazily on the first analysis request.

curl http://127.0.0.1:8080/health
nvidia-smi

Port collision with my previous project: the Holo/llama.cpp setup also uses port 8080. Stop that server before starting this app on 8080. If both are needed, choose another Uvicorn port and update the Tailscale Serve target to match.

7. Recording format and server processing

Earlier recordings sometimes failed both browser decoding and server analysis. One old client uploaded a blob under the filename reading.wav, but changing a filename alone does not convert audio into WAV. The revised recorder uses Web Audio to produce PCM WAV bytes.

The server saves each upload temporarily, invokes FFmpeg to convert it to 16-kHz mono audio, and limits decoding to 30 seconds. Uploads are capped at 8 MiB. Reference text must contain between 1 and 300 characters; the app therefore splits articles into short passages.

Recognition specifies Swedish, beam size 5, voice-activity filtering, and no conditioning on previous text. The response contains a transcript, the configured model name, time-stamped recognition segments, and a word alignment. Temporary uploaded and converted files are removed after the request.

Browser-side rhythm feedback estimates voiced duration, reading pace and longer pauses from recording energy. Those measurements are useful for replay and practice, but they are not a pronunciation score.

8. Article reading and original audio

Saved articles show the full text above the passage practice card. Full-text synthetic reading queues short chunks in order. The active chunk is highlighted and scrolled into view; word highlighting depends on the browser delivering speech-boundary events.

The v12 update added an MP3 picker to each article. Audio is stored in IndexedDB, while article text and learning progress use localStorage. That avoids trying to store multi-megabyte audio in localStorage. The original lesson MP3 could then be selected for natural playback instead of relying on the phone's synthetic voice.

Original MP3 playback does not yet have synchronised word highlighting. It has no matching word-time alignment in the current app. Browser TTS boundary events cannot be reused as timestamps for a different recording.

Text, progress and attached audio are local to the browser and site origin. Articles saved on the Ubuntu localhost site do not automatically appear on the phone's Tailscale URL. Clearing site data removes these saved items. The source lesson recording is not published with this blog post.

9. Reach the app from Android with private HTTPS

Microphone access requires a secure browser context. A plain LAN address such as http://192.168.x.x:8080 is not the same as the localhost development exception on the computer. I used Tailscale Serve for an HTTPS endpoint reachable within my tailnet.

  1. Install Tailscale on the phone and sign in to the same tailnet as the Ubuntu workstation.
  2. Turn on the phone's Tailscale connection.
  3. Keep Uvicorn running in the first Ubuntu terminal.
  4. In a second terminal, run the foreground Serve command:
sudo tailscale serve http://127.0.0.1:8080

The first attempt said Serve was not enabled and printed an activation link. After enabling it through the Tailscale page, running the command again produced an HTTPS *.ts.net address and a proxy to the local service. Open the exact printed HTTPS address in Android Chrome.

The published example intentionally omits my device hostname and tailnet identifier. This uses private Serve, not public Funnel. In foreground mode the Serve terminal must remain open; Ctrl+C ends it. I did not configure model auto-start tonight.

10. Fixing Swedish speech on a Xiaomi phone

The first Android test reported that no Swedish voice was available. The Xiaomi phone initially offered only its system speech engine and a few languages. I installed Google's Speech Recognition & Synthesis app, selected the Google engine in the system text-to-speech settings, and checked its Swedish voice options.

Restarting the phone resolved the issue in this test: the app then showed a Swedish sv_SE voice and could read text aloud. Settings names and available voices depend on the phone, OS and engine; this is the fix observed on my device rather than a universal guarantee.

The app gets voices from the browser's speechSynthesis.getVoices() and handles voiceschanged. It does not contain its own Swedish TTS model. Recorded MP3 playback and server transcription do not require a Swedish TTS voice.

11. Diagnosing “local model unavailable”

The phone successfully recorded about nine seconds and displayed rhythm feedback, but then showed Failed to fetch. That message meant the browser had not received a usable response from the analysis request; it did not identify the recognition model as the cause.

The initial Uvicorn log only showed GET requests for interface files. Those logs established that the page had been loaded, not that a later recording had reached /analyze. A normal Uvicorn access entry may also appear only after a request finishes.

For a connection check, open the following on the phone, replacing the placeholder with the actual Serve hostname:

https://YOUR-SERVE-HOST.ts.net/analyze

A GET should return 405 Method Not Allowed, because this endpoint expects POST. That is a useful reachability check, not a model execution test. On Ubuntu:

curl -i --max-time 10 http://127.0.0.1:8080/analyze
sudo tailscale serve status
tailscale status

In tonight's case the phone could not open the HTTPS endpoint. The cause was simple: Tailscale had been switched off on the phone. Turning it back on restored access, and the next recording was successfully recognised.

A cached PWA interface can still open, play local audio and record while its backend is unreachable. A working screen is therefore not proof that the model service is connected.

12. Normal use and installation

For the current workflow, three things must remain available: the phone's Tailscale connection, the Ubuntu Uvicorn process, and the Ubuntu Tailscale Serve process. The workstation also needs to remain awake.

Chrome offers “Add to home screen” or “Install app” for compatible web apps. That is the immediate PWA installation route. Tonight's confirmed result was successful phone-browser recording and recognition; a standalone APK build and a completed home-screen installation were not separately verified.

Wrapping the interface in an APK would not remove its dependence on the workstation model. Making analysis available with the computer turned off would require a different backend or an on-device model. A future manual launcher could reduce startup steps without loading a GPU model automatically at boot.

13. What the feedback can and cannot tell me

Words are aligned with edit distance so that one missing word does not make every later word look wrong. A red word means the transcript and target differ. It does not establish which phoneme was wrong, whether the vowel was too short, or whether Swedish word stress or pitch accent was correct.

Recognition can normalise a learner's pronunciation into the intended word, or produce incorrect text from unclear audio. More accurate Swedish transcription is useful, but it is not evidence of validated pronunciation assessment. I still replay the recording and compare it with the lesson audio.
