From KITTI to CARLA: my perception learning path

Yali Nie · September 2026

The goal is to move from reading sensor data to running a system. I’ll start with KITTI to understand geometry, train a 3D detection baseline, and then connect inference to CARLA.

Stage 1: understand data and geometry

Select a small sample from the official KITTI dataset. Read camera images, LiDAR point clouds, and calibration files. Transform LiDAR points into the camera frame and project them onto the image. Check whether projected points and 3D boxes align.

  • Verify coordinate conventions, units, axis directions, and matrix multiplication order.
  • Align timestamps and discard points behind the camera.
  • Save several overlays and inspect failure cases by eye.

Stage 2: run a 3D detection baseline

Use OpenPCDet to run a baseline such as PointPillars. Reproduce an official configuration first. Then change one variable at a time, such as voxel range, batch size, or input point count. Record accuracy, inference latency, and GPU memory use.

An RTX 4080 with 16 GB of VRAM is suitable for KITTI data processing and many baseline experiments. Exact memory use depends on the implementation, batch size, and input configuration. Measure before changing settings to address out-of-memory errors.

Stage 3: expand to multiple sensors and simulation

Use the nuScenes mini tutorial to learn a multi-camera data format. Then use CARLA to generate synchronized camera and LiDAR data and map detection results back into the simulated scene. Focus on timestamps, sensor extrinsics, latency, and failure handling.

Artifacts I want to keep

  • Reproducible environment and data preparation instructions.
  • Projection overlays, bird’s-eye views, and failure examples.
  • Baseline metrics with latency and memory measurements.
  • A short demonstration from CARLA sensor capture through model inference.
